# 图像裁剪、Diffusion Policy 原理与反思

[返回本分支 README](../README.md) · [返回 `main`](https://github.com/Zeil6/lerobot-so101-imitation-learning/tree/main)

## 图像裁剪不是缩放

原始相机图像为 1280×720，而原模型配置中出现 `crop_shape=(84,84)`。当前使用的 LeRobot 版本只支持 `crop_shape`，不支持 `resize_shape` 和 `crop_ratio`。

我后来意识到，`crop_shape` 的含义是从原图截取一个 84×84 区域，不是把整张 720p 图像缩小到 84×84。如果任务中的胶水、夹爪和黑盒没有同时落入这个小区域，模型得到的观测就不完整。

训练阶段若使用随机裁剪、部署阶段使用中心裁剪，还会引入输入分布差异。即使参数 shape 一样，画面语义也可能不同。

下一轮训练计划使用更合理的中央区域，例如 `[360, 640]`，但这个数值目前只是候选方案。真正采用前必须分别可视化 `handeye` 和 `fixed` 的裁剪结果，确认胶水、夹爪和黑盒在任务关键阶段都可见。

不能只在部署现有 checkpoint 时把 84×84 改成新尺寸。旧 checkpoint 学到的是旧预处理下的视觉分布，训练和部署必须同步修改并重新训练。

## 我怎样理解动作去噪

一段真实示范动作可以看成一个有结构的序列：接近胶水时位置变化连续，夹爪在合适时刻闭合。训练时对这个动作序列逐步加入噪声，让它越来越像随机信号；网络观察图像、机器人状态、噪声级别和被污染的动作，学习预测噪声或对应的去噪方向。

推理时没有现成的未来动作，因此从随机噪声序列开始，反复调用网络去掉一部分噪声，最后恢复出符合当前观测的候选动作序列。

## DDPM 与 DDIM

- DDPM 通常按较完整的随机反向过程逐步采样，步数多、计算开销大。
- DDIM 可以用更少的采样步骤生成序列，更适合受实时性约束的部署，但步数减少过多也可能损害动作质量。

`num_train_timesteps` 描述训练时构造噪声过程的时间离散范围；`num_inference_steps` 描述部署时实际执行多少次反向去噪。两者不是必须相等，也不能把“训练 100 个噪声等级”误解为“部署一定要执行 100 次”。

## `horizon`、`n_obs_steps`、`n_action_steps`

- `horizon`：模型处理/生成的序列时间范围。
- `n_obs_steps`：条件中使用多少步历史观测。
- `n_action_steps`：从生成序列中实际送入控制队列执行多少步。

它们共同决定模型看多远、生成多远和真正开环执行多远。只改单个参数而不看控制频率和推理时间，容易把问题从“队列耗尽”变成“执行旧动作太久”。

## 多模态能力与块切换

面对相似画面，抓取可能存在不止一种合理接近路径。扩散模型能够表达多种动作模式，而不是被迫只回归它们的平均值。这是优势，但在真机连续控制中也需要约束：相邻时刻若采到不同模式，两个动作块的边界可能变化明显。

## 阶段性反思

我最初认为抽动主要来自数据不足。扩充数据后问题仍在，我才开始检查模型何时推理、一次推理要做多少轮去噪、动作队列何时耗尽。

DDIM 16 步明显减小抽动周期，让我意识到训练成功和实时部署成功是两个不同终点。训练 loss 只覆盖其中一部分；推理时间、控制频率、动作分块、图像处理和硬件通信共同决定机器人是否连续。

我后来也修正了对 `crop_shape` 的直觉：看见 `(84,84)` 时不能默认整幅画面被缩放保留。下一轮实验前，我会先把训练和部署实际送入模型的图像保存成无隐私的样例，再决定裁剪范围。
